# QwenASR 系统优化方案

检查日期：2026-09-10。范围：实时录音、文件转写、课程回放获取、AI 精修与笔记、存储、启动和恢复。

建议先完善任务调度、恢复和性能统计，再做界面整合及模型评估。保留用户手动选择课次的方式，不增加漏录检查或历史课程自动补录。

## 当前状态与证据

- 本轮检查时主服务空闲，AI 任务列表为空，课程平台已连接；资料库有 10 条录音。
- 本机录音库接口连续三次耗时 11.9 / 9.7 / 9.6 ms，响应约 250 KB；AI 任务接口约 10 ms，课程状态接口约 1 ms。当前资料库查询不是主要性能瓶颈。
- 上一轮已通过 78 项测试，并用两节真实课堂的约一分钟片段验证分段转写、精修及笔记生成。本轮是代码与运行状态检查，没有重新转写整堂课，也没有进行满负荷压测。
- 已有分段下载、ASR、AI 并行、分段去重和断点恢复基础。下列内容是进一步优化，不能把已具备的功能重复计算为新增收益。

## 优先事项

## 1. 先建立性能基线

目前模型返回的 `latency` 从获取推理锁之前开始计时，包含排队、可能发生的模型加载和真正推理。直接把它当作纯模型速度，会误判瓶颈。证据：[model_runtime.py](../qwen_asr_app/model_runtime.py)。

为每个音频段记录：开始下载、下载确认、进入 ASR 队列、模型开始/结束、进入精修队列、AI 开始/结束、最终归档时间。同时记录音频时长、字数、失败次数和实际 API usage；服务未返回用量时明确标为未知。

用同一批中文、全英文、中英混讲、含数字公式、静音与噪声片段评测。分别测模型冷启动和已加载状态，再测实时录音与回放同时运行。短片段用于快速回归，完整两节课用于验证长时间运行和后半节覆盖。

验收：能够回答“一堂课分别花了多久、卡在哪个阶段、首段文字多久出现”，并区分真实测量与预计剩余时间。确认基线之前不承诺固定倍数提速。

## 2. 统一任务生命周期和恢复

目前任务状态分散在主服务、课程服务的全局变量、导入记录和录音元数据中。统一启动器现在管理同一个本地服务。证据：[smartclass_service.py](../qwen_asr_app/smartclass_service.py)、[course_stream.py](../qwen_asr_app/course_stream.py)、[start_qwen_asr.command](../start_qwen_asr.command)。

建议主服务保存唯一的任务台账：任务、源视频、音频分段、阶段状态、重试次数、用户是否暂停、配置版本及恢复位置。先落地任务台账；随后可用 SQLite 事务统一保存任务和段落，音频仍保持普通文件，便于导出和迁移。

恢复时同时检查分段文件和提交记录，处理“文件已落盘但任务记录尚未更新”的中断点。只恢复用户已经提交且没有主动暂停/取消的工作，不创建新课次任务。重启前检查所有下载、推理、精修、总结和录音任务，提供明确的继续运行、等待完成和保存后退出行为。

统一启动器管理一个本地服务与模型子进程，课程回放挂载在 `/course/`，避免重复实例和第二个端口。

验收：关闭页面、切换网络、重启服务后，已确认的音频和文字不会丢失；人工暂停的任务保持暂停；不会误把仍需精修的内容显示为完全结束。

## 3. 优化调度，保护实时录音

所有转写请求目前竞争同一把推理锁。后台一次较长推理进行时，新来的实时请求无法立即处理。另外，AI 队列有容量限制，课程工作线程等待向满队列提交时，会暂停后续 ASR。证据：[model_runtime.py](../qwen_asr_app/model_runtime.py)、[batch_pipeline.py](../qwen_asr_app/batch_pipeline.py)、[course_stream.py](../qwen_asr_app/course_stream.py)。

建议增加按任务类型调度的队列：实时定稿优先，过时的滚动预览可合并或取消，回放转写利用余量。正在执行的 GPU 推理不强行中断；检测到实时录音时，缩短后续后台分段，减少一次占用时间，并设置公平性规则避免后台永久等待。

精修任务先持久化入队，由独立消费者处理。AI 服务慢、限流或暂时失败时，继续下载和保存原始转写；达到明确的磁盘或待处理量上限后再有控制地暂停。不能把当前有界队列简单换成无限内存队列。

AI 请求按服务地址复用连接，并按服务统一限制并发。目前每次 AI 请求会新建客户端；跨功能的并发也需要统一计算。证据：[ai.py](../qwen_asr_app/ai.py)。首段可试验更短的分块，后续再恢复约一分钟分段，以评测结果选择长度。

验收：模拟 AI 请求持续缓慢时，后续原始转写仍能保存；同时录音和导入时，实时等待时间受控、后台有进展；同一账号的实际并发不超过配置上限。

## 4. 用原始视频身份处理去重和补齐

当前课次标识来自整组视频 ID 的哈希。单节 A 与两节 A+B 是不同标识，因此先单独导入 A、后导入 A+B 的场景可能再次处理 A。证据：[smartclass.py](../qwen_asr_app/smartclass.py)。

建议分别记录“原始视频”和“合成课堂”：每个视频只对应一份已确认的源音频，课堂通过引用决定顺序。第二节晚到时，用户选择补齐已有课堂；有歧义时展示两段日期、时间、课程与教师供用户确认归属。保留单节获取，也允许手动拆分错误配对。

验收：先导入 A，再选择 A+B，只获取缺少的 B；最终仍是一堂课、连续时间轴，已有段落和手动编辑不被覆盖。只有源音频版本变化时才重新校验和处理。

## 5. 减少磁盘重复写入，保证数据一致

目前每次段落更新都会触发全量保存，转写 JSON、原始文本、精修文本等随之重写。下载 ZIP 时也会重新打包。录音库读取则遍历文件加载元数据与转写。证据：[storage.py](../qwen_asr_app/storage.py)。当前十条录音规模下读取很快，因此资料库索引可随任务存储改造实施，不必单独抢先重写。

建议把段落更新与用户导出分开：先事务提交新增或修改的段落，再按版本号合并生成 TXT/Markdown；最终导出立即刷新到最新版本。ZIP 按录音内容版本缓存，内容未变则直接返回已有文件。课程来源和合并时间映射也应进入导出包。

多个 AI 任务和人工编辑对同一录音写入时，使用统一写入入口和版本检查；AI 完成时不能覆盖它开始之后的人工修改。SQLite 迁移保持旧文件可读、可回退，避免一次重写所有存储功能。

验收：已提交内容在强制中断后可以恢复；未编辑的导出重复下载不重建；增加到数百条录音时，列表通过分页与索引保持可用。

## 6. 整合界面与连接诊断

统一提供“实时录音 / 上传文件 / 课程回放 / 任务 / 资料库”入口。任务卡片展示下载、转写、精修、笔记四个独立进度，清楚区分“原文可读”和“笔记完成”。提供逐阶段重试、查看已完成文本、暂停与继续。

目前登录报错已经细分，但刷新课程与获取课次仍有统一概括错误，课程与回放列表也主要保存在内存中。建议增加：

- 按用户操作触发的诊断，分别检查本机服务、学校认证、课程接口、视频服务器和 AI 接口。
- 缓存最近成功加载的课程列表，标注更新时间；网络中断时仍能查看本地资料。
- 会话过期时按明确状态重新认证；保留密码提交不盲目循环重放的规则。
- 网络恢复后继续已提交任务。不会因此开始监控漏录或获取未选课次。
- 先把页面隐藏时的轮询降频；需要更及时的进度时使用事件推送，重连再读取完整快照。

验收：某个服务不可用时，其他可用功能继续工作，用户能看到失败阶段和有效的下一步操作。

## 7. 把精修质量作为提速约束

保留原始识别、精修和笔记三个层次及其版本。对数字、单位、正负号、否定条件、术语和语言变化做差异提示。未开启翻译时，精修应明确保持原语言；听不清的内容标注待核对，不自动补出数字或公式。

笔记中的章节、公式和例题关联已有转写段落，点击可播放对应合并音频，并查看原始课次。局部改错只重跑相关精修和受影响的笔记任务，避免重新下载、转写整堂课。

验收使用固定中文、英文及中英混讲样本；检查首尾内容、跨段连续性、例题条件及公式。文字差异检查只能提示可疑改写，不能替代人工核对关键内容。

模型评估放在调度与测量完成之后。保留当前 BF16 作为基线，对候选配置同时比较速度、内存、术语准确性和内容遗漏；达到质量门槛才更改默认值。

## 8. 收敛配置和测试环境

目前 AI 密钥按功能保存，没有绑定服务身份，浏览器和本机文件都有副本。建议用服务地址与明确的凭证 ID 关联功能配置，避免更换接口地址后沿用不匹配的密钥。学校密码与 AI 密钥可逐步迁入 macOS 钥匙串；页面只显示是否已保存、更换和删除入口。

上轮已修复一个具体测试误写真实密钥的问题；下一步应统一注入应用数据目录和密钥存储，所有测试默认使用临时目录与模拟接口。增加套件级断言，验证真实资料库和凭证文件没有变化。需要真实学校或 AI 服务的集成测试单独启动，并明确测试对象。

当前依赖是宽版本范围，建议保存已验证的精确锁定版本，升级时运行固定样本和恢复测试。项目目前无 Git 仓库；建立本地版本管理并排除凭证、录音与模型权重，保留可回退版本。

`app.py` 约 2,200 行、`static/app.js` 约 2,700 行，仍集中处理多个功能。随每轮改动逐步拆出录音、课程、任务、资料库和设置模块，保留现有 API 与文件兼容；每次只迁移一个职责并运行对应回归测试，避免为了整理目录一次重写全系统。

验收：完整测试不读写真实密钥、不产生真实云端笔记；换 AI 服务不会自动带入另一个服务的凭证；升级失败可以恢复代码和数据。

## 推荐实施顺序

第一轮交付性能统计、统一任务状态与退出保护、实时优先调度、源视频去重、测试全局隔离。重点验收断网、单节补齐、重复点击、同时实时录音与导入、程序重启和配置保持不变。

第二轮交付独立精修队列、AI 连接复用、增量保存和导出缓存。用同一套课堂样本比较优化前后耗时与质量，再进行完整两节课的长时间验证。

第三轮交付统一页面、诊断与缓存、笔记版本和时间跳转、全文搜索。候选模型的选择以第二轮性能数据与质量评测为依据。

完成标准以“选中一堂课后能够稳定处理、错误可解释、内容可核对、恢复不重复”为核心；不以新增按钮数量或单个短片段的最快成绩作为系统完成标准。

## 第一轮验收清单

1. 同一课次连续提交 10 次只创建一个课堂任务，网络响应丢失后重发音频段不重复保存。
2. 分别在音频写入后、转写完成后、精修完成后模拟进程退出；恢复时校验源音频与最终时间轴，没有缺段或重复段。
3. A 已导入、B 后上线时，只处理缺少的 B；已有人工修改保持不变。
4. 同时进行实时录音和后台导入，记录实时请求排队的中位数和 95 分位数，与优化前的同一场景比较；不凭主观感觉判定提速。
5. 模拟 AI 接口持续缓慢或限流，下载与 ASR 可以推进到配置的缓冲上限；停止后已确认数据可恢复，内存不会无限增长。
6. 所有自动化测试使用临时数据与模拟接口；测试前后真实凭证文件与真实资料库保持不变。
7. 中文、英文、中英混讲测试片段的数字、术语、否定条件和语言保持规则通过核对；首段加速不能以明显遗漏内容为代价。

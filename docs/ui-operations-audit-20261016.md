## 操作复现与修复

### 1. 筛选范围不等于操作范围

构造两门课程，每门包含不同类型的处理步骤。选择 Optics 课程和“课后复习笔记”，再全选重试：原版仍发送同课堂的 ASR；点击“重试当前失败步骤”还调用全局重试，带上另一门课。“收起已完成记录”同样从全局列表取目标。

修复后显式冻结点击时的课程、类型、状态和搜索过滤结果；只提交相应任务 ID，保留后端声明的 retry/continue 动作和 history_generation。共用队列按 owner 去重，默认全选不隐式选择队列控制。类型筛选也重新计算卡片错误数量和状态，避免只显示一个步骤却统计隐藏步骤。

### 2. 部分成功后失败项也被取消勾选

选择两个任务，模拟其中一个返回冲突。原版清空全部勾选。现在仅移除服务端确认成功的任务，失败项保持勾选并显示原因，便于定向重试。

### 3. 自动刷新扩大课程范围、丢失焦点或清空列表

选中课程后，下一次响应不含该课程，原版下拉框退回全部课程。刷新还会使结果链接的键盘焦点消失；格式不完整的任务响应会被当作空列表。

现在保留选中的课程，即使暂时没有任务；按任务和链接身份恢复焦点；不完整响应显示错误并保留已有列表。另回归了旧刷新不能覆盖操作后的状态、断网后恢复和切换筛选清除旧选择。

### 4. PDF 旧请求修改新弹窗

输入 old.pdf 并提交，响应延迟时按 Escape，重开弹窗输入 new.pdf，再释放旧响应。原版会关闭新弹窗、清空新路径并修改用户已经切换的筛选条件。文件选择器迟到结果也会覆盖其间手动编辑的路径或进入下一次弹窗。

新控制器按弹窗会话和输入版本判断响应归属；旧请求只报告自身结果，不修改新草稿和筛选。选择器运行时禁止提交；提交时禁止再次选择；取消选择保留输入。空白路径、重复路径、20 文件上限在请求前处理。入口移除 new=pdf 时保留 category、embedded、其他查询参数和 fragment。

### 5. 保存中的新编辑被旧响应覆盖

将远程地址改成 A 并保存，等待响应期间改成 B。原版响应会重新填入 A。MinerU 档位具有相同问题。连接测试期间从 A 改成 B，原版还会把 A 的成功结果展示为当前连接成功。

设置控制器区分已确认配置和表单草稿，记录输入版本。旧响应可以更新已确认快照，但不能覆盖较新的输入或证明新地址可用。保存与测试串行；读取失败撤销 ready 状态；初始读取期间保护表单。失败后保留草稿并允许重试，省电策略仍只在保存确认后生效。

### 6. 数字输入为空变成 0，折叠内错误不可见

清空 MinerU 页数输入框后保存，原版通过 Number('') 提交 0。把高级参数设置为越界值后收起面板，保存报错没有展开定位。

现在空白数值不提交，错误字段所在的 details 自动展开并获得焦点。切换档位保留暂时不生效的高级参数，恢复推荐值仍只是草稿，点击保存才生效。

### 7. “重新读取备份进度”实际重复创建

初次 GET 失败后，原版按钮虽然显示重新读取，点击仍可能 POST 创建。POST 结果不明时，再点也可能重复创建；导出过程中切换设置页会触发并行读取并重新启用按钮。

现在读取与创建共用单一在途操作；状态不明必须先 GET 核对，不能直接重复 POST。空状态清理旧进度文案，released 状态清除下载目标，结构不完整的响应不能解锁创建。

### 8. 已丢弃的录音被迟到响应改回处理中

发起丢弃，先收到 recording_discarded 事件，再收到早先 POST/GET 的 discarding 响应。原版重新加入 pending；迟到错误也可能报告已经完成的操作失败。

现在以录音 ID 和每次尝试的 token 判断响应归属，在 await 后再次检查。已完成事件优先，旧尝试不能完成新重试。POST 的 JSON 解析失败视为结果未确认并查询状态，不直接断言丢弃失败。两次确认、取消，以及确认后切换录音的目标隔离均回归。

### 9. 工作台继续处理缺少客户端请求头

工作台 POST /api/tasks/action 未带任务路由要求的 X-QwenASR-Client: task-center，重试和继续被拒绝。补齐该请求头并增加请求超时，保留 use_saved_ai_settings 语义。浏览器点击回归覆盖重试、继续、失败后再试、只打开笔记不触发任务，以及防止在途重复提交。

### 10. 带入上一轮自动保存修复

保存请求尚未完成时，将笔记改回已确认文本，仍需等待服务端确认或补偿保存；不能提前显示“已自动保存”或取消不确定结果的核对。相关 8 项 Node 回归再次通过。

## 复运行

从仓库根目录运行：

```bash
python -m pip install -r tests/browser/requirements-operations.txt
python -m playwright install chromium
python tests/browser/operations_audit.py
node --test tests/test_task_scope_ui_audit.cjs
```

已安装 Chromium 时，可用 `--chromium /path/to/chromium` 指定；`--match tasks_` 只运行任务组；`--source-root` 可指向另一份 checkout；`--output` 指定证据目录。输出默认在 `output/operations-audit`。测试依赖与生产模型依赖分开，不下载模型。

## 验证层级与尚未验收内容

任务中心使用完整生产 tasks.html、CSS、tasks.js 及其依赖，真实执行点击、输入、勾选、键盘操作、390px 窄屏和深色主题检查。设置、备份、录音丢弃、继续处理使用生产模块和独立组件 DOM 夹具，不是完整 app.js 工作台联调。

## AI 总结自动保存

Markdown 源码和逐段编辑均在停止输入约 900 毫秒后保存。离开编辑框、关闭笔记或切换到后台时会提交保存。成功后不重绘编辑区，避免旧请求返回时覆盖新输入或打断光标。每份笔记使用独立的串行保存队列。

每次修改同时保留浏览器本机草稿。暂时断网时保留草稿，进行有限重试；重新打开笔记时恢复。正常状态不显示“保存修改”按钮；失败时显示保存状态和重试入口。若另一页面或生成任务已更新正文，会保留当前草稿，供核对后点击“保存当前版本”。

自动保存只写入本地 QwenASR 笔记。推送到闪念贝壳仍使用用户原来的手动推送操作。

## AI 取名直接应用

“AI 取名”调用生成接口时携带 `apply: true`。后台生成标题后直接调用现有录音改名逻辑，保存名称并更新录音目录，再返回结果；页面更新录音库，无需再次点击保存。分类使用录音当前已保存的分类。

## MinerU 的 UTF-8 报错

本机安装的 MinerU 3.4.4 使用 mlx-vlm 0.3.9。错误出在 `BPEStreamingDetokenizer.add_token`：当下一 token 以空格开头时，把已积累的字节用严格 UTF-8 解码；非法字节会抛出 `UnicodeDecodeError` 并中断整份文档。报错位置属于模型输出解码，不能据此判定原 PPT 文件损坏。日志中的服务关闭是失败后的清理过程。

2026-09-12 再次报错时确认：工作台后台进程在 10:25 启动，旧兼容代码在 11:06 写入，因此后续转换仍由未重启的旧后台启动，未携带兼容加载配置。

现改为 `qwen_asr_app/mineru_runtime_patch.py`，直接对选定 MinerU 独立环境的 `mlx_vlm/tokenizer_utils.py` 安装小范围补丁：仅替换已知的 BPE 流式解码方法，原子替换以避免修改 uv 共享缓存中的硬链接文件。补丁版本为 `incremental-utf8-v2`。已于 2026-09-12 12:41（本机时间）在实际环境落盘，下一个新识别进程即可读取；已经启动的识别进程仍使用其内存中的旧代码。

原文件和补丁校验值存放在 `~/.qwenasr/compat-backups/mineru-mlx-utf8/<原文件 SHA-256>/`。工作台更新后的启动逻辑会在每次启动 MinerU 前检查补丁，已安装时直接复用；将来依赖升级导致代码结构变化时会明确停止修改。原来的 `PYTHONPATH` 加载脚本不再使用。

新解码器增量积累字节：尚未完整的 UTF-8 字符等待后续 token，确实无效的字节使用 `�` 标记并写出警告。课程资料库会指出生成 PDF 中含此标记的页码，原有 PDF 工具会在完成状态中提示核对。标记表示字符未能还原，应对照原页检查。

# Qwen3-ASR 本地语音工作台

本项目仅维护浏览器界面及其本地 Python 服务。

面向 Apple Silicon Mac 的本地实时语音转写网页。ASR 使用 `mlx-community/Qwen3-ASR-1.7B-bf16`：由官方 Qwen3-ASR-1.7B 转换而来的完整 BF16 权重，不做 8-bit/4-bit 量化，并通过 MLX 使用 Apple Silicon GPU。麦克风音频只在本机处理。可选的 AI 修正、整理、总结和中英互译通过 OpenAI Responses API、Chat Completions API 或兼容的本地 `/v1/responses`、`/v1/chat/completions` 服务完成；五个 AI 功能各自使用独立配置。

所有页面共用浏览器主题按钮。首次打开时跟随系统的浅色 / 深色偏好，手动切换后保存在当前浏览器的 Local Storage；主题只改变界面颜色，不会修改录音、课程资料或 AI 配置。

## 页面入口与录音库

启动后顶部提供五个平级入口：**录音工作台**、**录音库**、**课程回放**、**课程资料库**、**任务中心**。录音库现在是独立页面，支持按标题、逐字稿和课堂笔记全文搜索；打开录音后可以点击时间戳回听，并从笔记中的“原文 S1”链接定位到对应片段。笔记在重新生成、手动修改或从 IdeaShell 拉取前会自动保留历史版本，可在“版本历史”中比较和恢复。

上传录音会先进入后台任务，关闭网页后仍会继续处理；任务中心可以查看、暂停、继续或取消上传转写。AI Key 会按接口地址保存，切换 Base URL 后不会把旧服务的密钥发送给新服务。所有 AI 功能还受同一服务的总并发上限约束，可通过 `QWEN_ASR_AI_TOTAL_CONCURRENCY` 调整。

## 最简单的启动方式

双击 `start_qwen_asr.command`。脚本会检查依赖和模型、启动两个后台服务后打开浏览器，模型在实际转写时加载。关闭终端不会停止服务。双击 `stop_qwen_asr.command` 可安全停止；仍有录音、下载、转写或 AI 任务时会拒绝退出，提示先在页面处理。

打开网页后先填写录音名称并选择或新建分类，再点击“新建并开始转写”。首次使用时允许麦克风权限。说话过程中会滚动显示识别文本，短暂停顿后生成正式段落。

- 主按钮只负责开始、暂停和恢复收音。暂停会立即停止收音并恢复按钮，剩余 ASR 和 AI 处理在后台完成；连接确认超时或断开也能恢复操作，无需刷新。
- “结束并保存”会完整保存 AAC、`原始转写.txt`、`AI修正后文本.txt` 和 JSON，然后自动用“AI 总结”提供商生成详细课堂笔记与录音库短摘要，新增 `AI总结.md`。ZIP 只在点击下载时临时生成，传输结束或中断后自动删除，不留在录音文件夹。与录音中的“实时总结”开关独立。
- 结束保存和 AI 笔记生成由后台任务执行，刷新或关闭网页不会取消已提交的任务。重开页面会恢复进度；若本地 Python 服务也被关闭，重启后会将未完成任务标为可重试。录音恢复会补转写磁盘中已保存但尚未识别的片段；AI 生成保留成功分块及原有笔记，可以重新生成，也可以单独重试短摘要。服务停止期间不会继续采音或调用 AI。
- 每次新会话都会立刻在资料库根目录的 `<分类>/<录音名称>__<编号>/` 中建立完整档案。可在网页“全部设置 → 资料库与设备”中选择资料库文件夹；点击“迁移并保存”后，现有录音和课程配置会迁移到新位置，目标目录里的其他文件不会移动。录音进行中或上传转写处理中不能迁移。录音进行中使用隐藏的可恢复 WAV 底稿，结束时转成单声道 16 kHz / 64 kbps AAC。
- 关闭网页、关闭浏览器或重启服务都不会把会话标记为结束。再次打开网页会恢复原会话和已有转写；受浏览器安全限制，关闭网页期间无法继续采集麦克风，重开后点击“恢复转写”即可继续。
- “上传录音一键转写”支持一次选择多个常见音频/视频文件。弹窗实时显示当前原始转写、AI 修正/翻译和总进度；文件 ASR 与远端 AI 精修重叠运行，精修、长文本整理和全局改写都按配置使用 1–8 路有界并发，完成后仍按原始时间顺序归档。处理后统一归档为 AAC，并提供按需生成、下载后自动清理的完整 ZIP。
- AI 修正和翻译可以在实时录音中随时切换。正在说的一句话继续使用原设置，停顿定稿后，下一句话使用新设置。仅在启用相应功能时才校验对应 AI 配置；关闭 AI 时不会强制验证无关提供商。
- 开启 AI 修正时，程序除逐句低延迟校对外，还会在每完成 5 分钟内容后进行一次整体复核。整体复核会结合上一窗口的末尾上下文，修复跨段断句、合并可连接的碎片段并重新组织自然段；页面以“AI 整体整理”卡片替换对应的小段，原始小段仍可展开查看。
- 开启“实时总结”后，录音过程中会按自定义间隔维护累计课堂总结，并使用独立的“5 分钟整理”提供商。课后详细笔记使用独立的“AI 总结”提供商，录音结束后自动生成，也可在录音库重新生成；上传转写完成后可手动生成。“长上下文整理”提供商只负责上传文件的全局长文本整理。五个功能页分别保存 Base URL、模型、Key、Context Window、接口格式、自定义参数、提示词和并发上限；默认 AI 总结 3 路，其余功能 2 路。
- 详细笔记优先将完整转写一次交给 AI，结合全文建立上下文联系。只有全文、实际提示词、JSON 编码开销及预留输出空间超过配置的 Context Window 时才分块；不再固定切成约 3,000 token。全文生成结果直接保存；超限分块仍保留按时间排序和失败重试能力。请填写对应服务实际支持的窗口；模型输出截断时明确报错，旧笔记保留。
- “AI 任务”页集中显示课后总结、实时累计总结和未精修内容，并提供“全部继续、全部暂停、全部重试”。临时 429 限流或 502/503/504 服务繁忙会按 15–300 秒退避并自动恢复（最多 6 次）；余额或总额度耗尽会停止自动循环并明确提示。输出截断、请求片段过长、JSON 损坏或段落映射异常会缩小连续分块后重试；已经成功的进度保留。同一时间窗口的旧版重复失败记录聚合为一项。

右侧“录音库”支持分类筛选、月历热力图和按日期查看。每条录音可在完成后生成 AI 总结，再根据总结和可配置提示词生成标题。点击“AI 取名”后直接保存新名称，无需再点击“保存名称与分类”。点击“查看笔记”会进入全屏左右分栏：左侧为逐字稿，右侧默认完整渲染 Markdown（标题、列表、表格、代码块、行内/块公式）。生成提示词强制数学内容使用 `$...$` 或 `$$...$$`；若兼容模型仍把明显公式写成单反引号代码，阅读与保存链路会将其规范为行内公式，同时保留真正的程序代码。点击某一段只编辑该段，其余内容继续阅读；编辑后约 0.9 秒自动保存，失焦或关闭笔记时立即保存，Esc 撤销当前段，⌘/Ctrl+Enter 完成。保存请求按顺序执行，返回时不重绘编辑区；网络失败会保留本机草稿，恢复页面后继续保存。与其他页面或任务发生内容冲突时保留草稿并提示核对。阅读器提供目录、展开阅读和 Markdown 源码入口，保存后重新打开仍保持原格式。也可以重新命名、移动分类、下载或删除；删除会把整条录音目录移到系统废纸篓。

完成后的 AI 总结可手动同步到 IdeaShell。首次在高级设置中点击“连接 IdeaShell”会打开 OAuth 授权页面，令牌与客户端注册信息以仅当前用户可读的方式保存在 `~/.qwenasr/`。点击推送后先展示实际内容预览，可选择“总结＋精修原文”“仅总结”或“仅精修原文”；默认是一条完整归档，上半部分 AI 总结、下半部分带真实时间戳的精修录音原文。尚未精修的片段会明确标注并保留原始识别内容，不会伪造时间戳。全屏笔记右上角可从已关联的 IdeaShell 条目拉取 Markdown，拉取时只提取“AI 总结”章节，避免把原文重复塞入总结。开发验证请使用模拟接口，不要创建真实测试笔记。

国内 IdeaShell MCP 已迁移到 `https://mcp.ideashell.cn/mcp`，兼容已有授权、旧笔记关联和附件去重。服务端目前的新授权限制，以及实测的文档格式、大小和自动文本提取能力，见 [IdeaShell MCP 迁移与附件能力](docs/IdeaShell-MCP迁移与附件能力.md)。

批量转写会将音频在约 90 秒处寻找静音位置切段，并把课程中的 `max_tokens` 当作上限，根据实际片段时长自动缩小。检测到异常重复输出时，长片段会自动二分重转；较短片段会裁去循环尾。单段超过 180 秒会终止，任务保留为“可继续”。服务或网页中断后，可以在录音库点击“继续处理”，从最后成功的音频时间点恢复。逐段 AI 结果会立即持久化；全局改写按 Context Window 安全分块并发处理，局部失败时保留已完成分块，下次只重试缺失部分。

## 南邮课程回放转写

双击 `start_qwen_asr.command`，或从语音工作台点击“课程回放转写”，进入 <http://127.0.0.1:8765/course/>（可通过 `QWEN_ASR_PORT` 修改端口）。语音工作台和课程回放由同一个本地服务提供，不再启动第二个端口。首次在本机页面填写统一身份认证账号密码；勾选保存后，以后启动程序会自行登录。账号配置只保存在 `~/.qwenasr/smartclass/credentials.json`（0600），不会读取浏览器 Cookie，也不会把密码发给 AI 服务。

选择本学期课程，再勾选需要获取的课次并点击“将选中课次加入队列”。运行期间仍可切换课程、刷新回放并继续追加课次，重复提交正在排队或执行的课次不会重置任务。程序仅处理选中课次，不检查漏录、不自动补历史课程。同一天同课程、教师一致、节次相邻且间隔不超过 10 分钟的两节回放会组成一堂课，标题取自回放标题中的课程名称。未配对的单节默认不可选，可明确开启单节获取。

课次列表按学校回放编号匹配本机录音库，已完成的课次显示“已入库”；两节中只有一节完成时显示“部分入库”，并列出各节状态。已提交的任务显示“已排队”“入库中”“已暂停”或“待继续”，状态会自动更新，刷新浏览器和重启服务后仍保留。改过录音标题也能匹配；删除录音后不会继续标为当前已入库。

右侧运行状态只显示正在执行和排队的课次，完成后自动移除；历史结果在录音库和任务中心查看。队列最多同时推进三个课次，其中两个下载通道可以重叠工作；下载结束就释放通道供后续课次使用，转写和笔记可继续在后台处理。本地 ASR 仍由现有模型调度器串行推理。同一回放来源的单节和合并课次会依次处理，避免同时写入一条录音。

每条课次右侧提供“上半节回放”“下半节回放”，未配对的课次提供一个“课程回放”按钮。尚未入库也可使用，从对应半节课的开头打开；点击回放不会勾选课次或触发入库。所有回放链接只开一个新标签页，在其中自动登录并定位，不再留下中转页面；需将已有油猴跳转脚本更新到 1.1.0，见 [油猴脚本说明](docs/SmartClass油猴回放跳转.md)。

课程回放的录音日期、时间、日历归属和排序使用 SmartClass 平台的上课时间，两节合并时取第一节开始和最后一节结束时间（北京时间）。`started_at`、`recorded_at` 记录上课开始，`ended_at` 记录已确认的平台结束时间；本地导入与归档时间分别保留在 `imported_at`、`archived_at`。旧课程可从来源记录恢复正确时间，普通录音和文件上传仍使用原有日期规则。

现在使用分段流水线：支持 HTTP Range 的媒体通过四个下载线程读取 8 MiB 分段，先获取 1 MiB 供解码器尽早读取，临时视频缓存使用磁盘并在结束或暂停后释放；不支持 Range 时沿用普通读取。从 `video1` 解码音轨，在约一分钟附近的低音量处切段；一段下载完成就立即交给本地 Qwen3-ASR，识别出的文字同时交给已配置的 AI 精修。页面分别显示下载分钟数、转写分钟数、精修段数。两节课保持一个录音条目和连续时间戳，收齐后归档成一个 AAC、逐字稿、精修文本和一份 AI 课堂笔记。整堂课笔记在全部转写完成后生成。下载、转写、精修相互重叠，但本地模型与 AI 服务本身的处理时间仍会影响总耗时。

“笔记设置”可分别调整精修和总结模型，或关闭任一功能。修改后自动保存到 `~/.qwenasr/smartclass/options.json`，也可点击“保存笔记设置”。首次未配置时采用工作台的本机 AI 配置，之后保留课程页自己的设置；页面导航不会覆盖它。密钥复用主工作台的本机密钥库。

选中的课次和提交时的设置会保存在本机队列。重启并登录成功后，只继续已经提交且没有主动暂停的课次。点击“暂停队列”后保持暂停，可用“继续已保存队列”恢复；不会查找漏录或自动新增课次。网络失败的项目保留进度，可手动继续。

重复提交课次或音频段会校验并去重。每个分段有落盘检查点，可恢复音频保存后、主记录写入前的中断。未完成分段放在 `.course-chunks/`；归档后清理分段，并保留 `.course-source.flac` 无损底稿供后续补课。先导入 A、后来选择 A+B 时，复用本地 A，只获取 B，保留已有标题和人工修改，补齐前在 `.versions/` 留一份备份。旧版没有无损底稿时复用已有 AAC；源顺序或归属冲突会提示核对。

实时定稿优先于滚动预览和后台 ASR；后台等待过久仍有执行机会。当前 GPU 推理完成后才能让出，出现实时请求时后续后台块缩短到最多 25 秒。精修缓冲上限为 512 个已保存文本段，不缓存音频；达到上限后才等待，AI 失败时原文保留。每堂课上限为 2 小时。课程页面显示首段文字耗时和 ASR 排队/推理耗时；`/api/health` 提供当前进程最近 500 次请求的 p50/p95 统计。

学校平台与视频服务器的网络可达性不同。网络切换后，程序会重新建立认证连接，对读取请求和视频读取最多重试 3 次；密码提交只尝试一次。失败信息显示具体步骤、服务器与超时/解析/连接类型。2026-09-10 在宿舍实测认证、课程列表与视频音轨均可访问，视频域名解析到校园内网地址；换到不通校园内网的网络时，需要先恢复对学校视频服务器的正常访问。

## 每门课程的独立设置

工作台左侧新增“课程资料库”（`/course-files`）：按课程拖入或多选课件、讲义、作业等文件，按内容去重，保留原件并按需生成 PDF。提供 Mac 文件剪贴板复制、下载、闪念贝壳笔记匹配与附件上传预览。文件保存在 `<资料库根目录>/<课程>/课程资料/`，迁移资料库时一同迁移。详细设计、格式支持与试用步骤见 [课程资料库设计与使用](docs/课程资料库设计与使用.md)。此功能依照本次要求未运行测试，等待用户试用。

左侧选择课程分类后，可直接点击“全部设置”，按资料库与设备、AI 模型与接口、课程提示词与识别、实时录音、本机保存和 IdeaShell 同步分区配置。课程配置可分别保存：

- AI 修正系统提示词；
- 发给 Qwen3-ASR 的课程背景、教师姓名和专业词汇提示词；
- 每行一个的课程术语库；同一份词库会以受控预算提供给 ASR hotwords/提示词及后续 AI 精修、整理和总结；
- 当前 MLX Qwen3-ASR 实现支持的生成参数：`max_tokens`、`batch_size`、`temperature`、`top_p`、`top_k`、`min_p`、`min_tokens_to_keep`、`repetition_penalty`、`repetition_context_size`、`prefill_step_size`、`chunk_duration`、`min_chunk_duration`、`hotwords`、`verbose`。

点击“保存此课程设置”后，配置同时写入应用设置和课程文件夹中的 `.qwenasr-course.json`。以后选择这个分类会自动载入。词库最多保存 500 条；ASR 最多取前 100 条且约占 1,200 tokens，后续 AI 按当前原文优先选词并最多占 4,096 tokens 或上下文的 5%，以较小者为准。`language` 在主界面选择，`system_prompt` 使用课程提示词；底层 `stream` 由网页的实时/批量流程接管，不作为自由参数开放。批量转写中的 `max_tokens` 是安全上限，程序还会按片段长度设置更小的实际值，以避免静音或噪声引发长时间重复生成。

默认滚动预览间隔约 6 秒，达到课程分段停顿时定稿。模型采用按需加载：点击转写时加载完整 BF16 权重，网页连接关闭、暂停或结束且最后一段处理完成约 5 秒后，自动卸载模型并清理 MLX Metal 缓存。Python 服务保留为低占用空壳，方便下次直接打开页面；下次转写会自动重新加载模型。

实时分段默认采用更适合课堂的设置：连续停顿 1.5 秒后定稿，单段最长 45 秒，滚动预览每 6 秒更新，并忽略有效语音不足约 0.55 秒的噪声小段。这三个主要时间参数可以在高级设置中调整并随课程保存；录音过程中修改会从下一段生效。

## Apple Neural Engine / NPU

当前 MLX 推理后端只提供 CPU 与 GPU 设备，不能把这个 Qwen3-ASR 模型直接切换到 Apple Neural Engine。要使用 Neural Engine，需要把完整的语音编码器、语言模型和生成流程转换并适配为 Core ML，且算子、动态长度和缓存都要验证；当前项目没有一个可保证精度和稳定性的现成转换。因此界面会明确显示 NPU 不可用，继续使用 Apple GPU + 按需加载/空闲卸载这一实际可用的节能方案。

## AI 修正与中英互译

ASR 不依赖任何 API Key。若要开启 AI 修正或翻译，可在网页的“AI 接口与高级设置”中填写：

- 接口地址：例如 `https://api.openai.com/v1`，也可以是兼容 Responses API 或 Chat Completions API 的本地服务地址。
- 模型：由对应服务提供的文本模型名称。
- 五分钟整理、长上下文整理、AI 精修和 AI 总结各有独立的模型与提示词；只有对应功能启用或被点击时才会发送请求。
- Context Window：默认提升为 131,072 tokens；填写值仍应不高于所选模型和服务商实际支持的输入与输出总窗口。程序会预留输出空间、裁剪最旧上文并对长录音分块；预计超限的单次请求不会发送。
- 最大输出 tokens：每个 AI 功能单独配置；详细总结默认 16,384，其余默认 8,000，程序会同时受 32,768 和 Context Window 一半的安全上限约束，并据此决定全文生成或分块生成。
- 接口格式：支持自动识别、Responses API 和 Chat Completions API。`https://api.siliconflow.cn/v1` 会自动使用 `/chat/completions`。
- 每个功能页的“测试连接”都会真正发送一条短请求，显示实际回复、耗时或具体失败原因；未启用的功能不会因为缺少其 API 配置而阻塞录音。
- DNS、连接和读取超时会分类显示并做有限退避重试。`nodename nor servname provided` 表示请求在域名解析阶段就失败，模型尚未收到内容，不是上下文过长或推理太慢。
- API 配置与 Key：接口地址、模型、参数和提示词保存到 `~/.qwenasr/ai-settings.json`；密钥独立保存在 `~/.qwenasr/ai-provider-secrets.json`，按接口地址绑定。两个文件均使用仅当前用户可读写的 `0600` 权限。网页优先恢复本机文件，清空浏览器不会丢失配置；旧浏览器配置在本机尚无配置文件时迁移一次。点击“清除已保存配置”才删除工作台本机配置、密钥及浏览器缓存。不要在多人共用的系统账户中保存私人密钥。
- 系统提示词与上文：每次修正都会携带可编辑的系统提示词、当前原始转写，以及默认最近 2,000 个字符的录音上文；上文长度可设为 0–12,000。
- 口语清理：所有 AI 修正都会附加一条保护规则，删除无语义的“啊、哎、诶、嗯、呃、额、呢”等填充词，并合并停顿或自我修正造成的名词/短语重复；有语法含义的语气、引用和有意强调会保留。
- 自定义发送参数：填写请求 JSON。默认是 `reasoning.effort: none`、低 verbosity 和 `store: false`；Chat Completions 会自动映射为 `enable_thinking: false`。`model`、当前文本和系统指令由程序保留管理。

也可以在 `.env` 中配置 `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`，以及按功能拆分的 `AI_REVIEW_*`、`AI_SUMMARY_*`、`AI_GLOBAL_*`、`AI_CORRECTION_*`。网页不会读取或显示服务端密钥；浏览器已有配置会迁移到五个独立设置页，不覆盖自定义提示词。

## 说话人区分

Qwen3-ASR 本身负责语音识别，不包含说话人分离（diarization），因此当前版本不会自动标记“说话人 1 / 说话人 2”。这需要额外下载并常驻一个说话人分离模型，会增加内存、耗电和处理延迟，未默认开启。

## 命令行启动

```bash
./start_qwen_asr.command
```

默认地址是 <http://127.0.0.1:8765>。本机 `localhost` 可以直接使用麦克风；若要让局域网其他设备访问，浏览器通常要求 HTTPS。

录音 WebSocket 默认仅接受本机同源页面。通过局域网域名或 HTTPS 反向代理访问时，在 `.env` 的 `QWEN_ASR_ALLOWED_ORIGINS` 中填写实际网页来源（例如 `https://asr.example.com`，多个来源用逗号分隔，包含非默认端口），重启工作台后生效。

## 目录说明

- `app.py`：轻量入口，只负责 FastAPI 路由、WebSocket 调度和批量任务编排。
- `qwen_asr_app/settings.py`：ASR、实时分段与默认提示词配置及校验。
- `qwen_asr_app/model_runtime.py`：可卸载的 MLX 模型子进程与超时管理。
- `qwen_asr_app/audio.py`：解码、静音附近切段和 AAC 转码。
- `qwen_asr_app/storage.py`：课程设置、录音条目、恢复、下载与废纸篓管理。
- `qwen_asr_app/ai.py`：Responses / Chat Completions 兼容层、无思考参数与文本校正。
- `qwen_asr_app/context_budget.py`：Context Window 估算、历史裁剪与安全分块。
- `qwen_asr_app/terminology.py`：课程术语种子、校验、ASR hotwords 合并与 AI 词库预算。
- `qwen_asr_app/batch_ai.py`：批量逐段修正、全局改写与总结。
- `qwen_asr_app/review.py`：异常重复检测、五分钟整理窗口与总结窗口规划。
- `qwen_asr_app/live_session.py`：实时收音、逐句转写、设置热切换、周期整体整理与总结。
- `static/app.js`：页面总调度；`static/js/` 中分离了音频采样、上传任务、录音库搜索、转写视图和总结视图模块。
- `models/Qwen3-ASR-1.7B-MLX-bf16/`：适配 Apple Silicon 的完整 BF16 模型权重。
- `app-settings.json`：录音资料库根目录、分类和历史资料库位置。
- `<资料库根目录>/<分类>/.qwenasr-course.json`：该课程独立的 AI 提示词、ASR 提示词和推理参数。
- `<资料库根目录>/<分类>/<录音名称>__<编号>/`：录音资料库；包含 AAC、`原始转写.txt`、`AI修正后文本.txt`、生成后的 `AI总结.md`、JSON、会话元数据和 ZIP。
- `recordings/`：旧版兼容目录；已有录音已迁移到默认资料库。
- `start_qwen_asr.command`：双击一键启动器。
- `server.log`：最近一次服务日志。
- `~/.qwenasr/uploads/jobs.json`：上传转写任务及可恢复进度。
- 录音目录中的 `.note-history/`：笔记历史版本。

## MinerU 4 文件识别

本地 PDF 工具和课程资料库使用 MinerU 4.0.10，运行在独立环境 `~/.qwenasr/runtimes/mineru4/`。首次安装或换机器时运行 `scripts/install_mineru4.command`，它会下载并校验 Apple Silicon 所需的小模型与 llama.cpp 视觉模型。模型保存在 `~/.qwenasr/mineru4/models/`，不纳入 Git。

打开“全部设置 → MinerU 文件识别”，或访问 <http://127.0.0.1:8765/?settings=mineru>。质量档位包括极速 Flash、基础 Basic、标准 Standard 和高级 Advanced；标准适合日常识别，高级使用更多推理计算，适合难识别的公式与排版。可调整自动／强制 OCR／原生文字层、图像分析、小模型后端、视觉引擎、模型下载来源、处理窗口页数、视觉并发和推理内存预算。内存预算影响小模型批量大小，不是进程内存硬限制；视觉并发也受本地引擎实际容量约束。Mac 推荐 Torch/MPS 自动后端和 llama.cpp。ONNX 需要对应模型；vLLM、LMDeploy 需要各自支持的操作系统、硬件与依赖。

点击“保存 MinerU 设置”后写入 `~/.qwenasr/mineru-settings.json`（0600）。新任务保存参数快照，运行中的任务保持原参数；继续或重试未完成文件时使用最新配置。既有结果不会因设置变化自动重做；课程资料库会显示“按新参数重新识别”。本地 PDF 工具保留同名结果保护，比较不同参数前需先重命名或移走原件旁已有的 `(AI).pdf`。所有页面在本机处理，不配置远程文档服务，也不继承全局远程视觉模型地址。

识别一次同时导出 Markdown、逐页内容列表和结构化结果，再把逐页正文、表格与 LaTeX 写入保留原页的 AI 友好 PDF。4.0 使用官方 Content List V1 渲染器适配打包器，避免沿用 3.x 的旧 JSON 结构；旧版 MLX 解码补丁不再参与 4.0 调用。官方档位和升级说明：[Tiers and Runtimes](https://opendatalab.github.io/MinerU/usage/tiers/)、[Migration to 4.0](https://opendatalab.github.io/MinerU/reference/migration_4/)。

## 回归验证

使用 `.venv/bin/python scripts/check_tests.py` 运行 Python 回归测试，并核对真实凭证、设置和录音文件没有被测试修改。测试自动使用临时 `QWEN_ASR_DATA_DIR`，网络请求必须模拟；不会登录真实学校账号或调用真实 AI。前端控制测试：`node --test tests/test_session_controls.cjs`。

`.venv/bin/python scripts/benchmark_scheduler.py` 仅比较模拟任务的排队策略，不能代表真实 ASR 提速。实际课堂的下载、模型加载、排队、推理、精修和归档耗时需从真实任务统计中评估。
